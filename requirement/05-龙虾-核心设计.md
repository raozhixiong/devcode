## 一、总体架构

### 1.1 进程模型（单进程 Gateway）

```
浏览器 ──HTTP(静态资源+REST)──┐
浏览器 ──WS(帧协议)───────────┤
                              ▼
                    ┌─────────────────────────────┐
                    │  LobsterGateway (Spring Boot)│
                    │  ├ WebServer (:18790)        │
                    │  ├ WebSocketHub              │
                    │  ├ SessionRouter             │
                    │  ├ CommandQueue (lane FIFO)  │
                    │  ├ AgentRuntime 池            │
                    │  ├ ToolRegistry              │
                    │  ├ EventBus (durable+live)   │
                    │  ├ CronScheduler (Quartz)    │
                    │  └ PluginHost                │
                    ▼                             ▼
             SQLiteStore                    FileSystemStore
        (lobster.db + agent 库)        (workspace/tool-output/snapshot)
```

- **本地启动**：`java -jar lobster.jar`（内置 Tomcat）；启动时自动建目录、跑 migration、起 WS
- **并发模型**：每 session 一个虚拟线程（Java 21 Loom）执行 AgentLoop；全局并发帽 `agents.maxConcurrent`（默认 CPU 核数）

### 1.2 模块依赖

```
ws(帧协议) ─┐
rest ────────┼─> services(session/agent/task/…) ─> agent(loop/prompt/llm)
            │        │                                ├─> tool(20+)
            │        └─> event(bus) <─────────────────┘
            └────────────┴─> store(sqlite + fs)
```

## 二、核心机制设计

### 2.1 Agent Loop（状态机）

`AgentLoopRunner`（每会话单实例，lane 内串行）：

```java
runLoop(sessionId):
  while (true):
    1. history = messageStore.loadActive(sessionId)   // 过滤已压缩
    2. last = history.last(); 若 last.role==ASSISTANT && finish != TOOL_CALLS -> break
    3. step == 1 -> titleAgent 异步生成标题
    4. 处理 inbox: prompt / subtask(@agent 直调) / compaction(溢出自动)
    5. reminder.inject(lastUserMsg)     // plan/build-switch/编辑器选区
    6. tools = toolRegistry.resolve(agent, model)
    7. assistantMsg = messageStore.createAssistant(sessionId)
    8. LlmStream stream = llmProvider.stream(prepare(history, tools))
       for event in stream:              // processor 投影落库
         TEXT_DELTA      -> partStore.appendDelta + live 事件
         REASONING_DELTA -> 同上
         TOOL_CALL       -> partStore.toolPending->running; doomLoop 检测
         TOOL_RESULT     -> 图片归一化 -> partStore.completeToolCall
         STEP_FINISH     -> usage/cost 累计 + snapshot patch + 溢出检测
    9. 孤儿 tool 补 interrupted 占位
    10. switch finish: STOP -> break; TOOL_CALLS -> continue; OVERFLOW -> compact 后重试
```

**输入收件箱**：`session.prompt` 先 INSERT session_input（admitted_seq），再由 loop promote（promoted_seq）——崩溃后重启重放未 promote 的输入。

### 2.2 消息与 Part 模型

```java
sealed interface Part {
  record TextPart(String text, boolean synthetic, boolean ignored) implements Part;
  record ReasoningPart(String text) implements Part;
  record ToolPart(String tool, String callId, ToolState state) implements Part;
  record FilePart(String mime, String filename, String url, FileSource source) implements Part;
  record StepStartPart(String snapshotId) implements Part;
  record StepFinishPart(String reason, Usage usage, String snapshot) implements Part;
  record SnapshotPart(String hash, List<String> files) implements Part;
  record PatchPart(String hash, List<FileDiff> files) implements Part;
  record AgentPart(String agentName) implements Part;
  record SubtaskPart(String prompt, String agent) implements Part;
  record CompactionPart(boolean auto, String tailStartId) implements Part;
  record RetryPart(int attempt, String error) implements Part;
}
sealed interface ToolState {
  record Pending(JsonNode input, String raw);
  record Running(JsonNode input, String title, JsonNode metadata, long startedAt);
  record Completed(String output, String title, JsonNode metadata, List<Attachment> attachments);
  record Error(String error);
}
```

- delta 事件 `{type:"session.next.text.delta", textID, delta}` 仅广播不落库；`ended` 事件全量落库可回放
- **投影**：part 表为 append-only 事件源；`session_message` 视图为投影结果（重放 = 从 event 表重建）

### 2.3 提示词组装器（PromptAssembler）

```
SystemPrompt = [
  ① 身份段: agent.prompt（角色模板：developer.txt/reviewer.txt/…）
  ② 稳定段（cache 边界上）:
     env 块（模型名/cwd/git/platform/今日日期）
     指令文件（全局 lobster/AGENTS.md -> 项目 findUp 首命中）
     bootstrap 注入（AGENTS/SOUL/IDENTITY/USER/MEMORY，20k/文件 60k 总额）
     MCP 指令 <mcp_instructions>
     技能清单 <available_skills>（带版本 hash）
     工具使用守则（角色差异化）
  ===== CACHE BOUNDARY =====
  ③ 易变段（cache 边界下）:
     日期时间+时区 / 频道上下文 / 运行时信息（host/model/thinking level）
     长任务指导（cron 而非 sleep 轮询 / spawn 而非轮询）
]
```

- 组装结果缓存 keyed by (agentId, toolsHash, bootstrapHash)，边界下变化不破缓存
- Reminders（`ReminderInjector`）：plan 模式/模式切换/后台任务完成 注入最后一条 user 消息的 synthetic part

### 2.4 工具系统

```java
public interface Tool {
  String id();                                  // "read" "edit" "task"…
  String description();                         // resources/tools/read.txt
  JsonSchema parameters();                      // JSON Schema draft-07
  ToolResult execute(JsonNode args, ToolContext ctx) throws ToolException;
}
public record ToolContext(
  SessionID sessionId, MessageID messageId, AgentInfo agent,
  AbortSignal abort,                            // 协作式中断
  Consumer<ToolProgress> metadata,              // 流式更新卡片
  Function<PermissionRequest, PermissionReply> ask  // 权限挂起
) {}
public record ToolResult(String title, JsonNode metadata, String output,
                         List<Attachment> attachments) {}
```

- **注册**：`ToolRegistry` 启动扫描内置 + `plugins/tools/*.java` ServiceLoader + MCP 远程工具
- **过滤链**：内置 -> 角色模板允许集 -> agent allow/deny -> 模型特例（gpt 系 apply_patch 替换 edit/write）-> 权限过滤后 MCP
- **task 工具 description 动态拼接**可用子代理清单（每次 resolve 重建）
- **截断管道**：`OutputTruncator`（2000 行/50KB，全文写 `data/tool-output/tool_<ulid>.txt`，7 天清理线程）
- **权限包装**：`PermissionedTool` 装饰器统一在 execute 前调 ctx.ask
- **doom loop**：`DoomLoopDetector`（callID 签名连续 3 次 -> ask）

### 2.5 权限引擎

```java
record PermissionRule(String permission, String pattern, Action action)  // allow|deny|ask
evaluate(request):
  rulesets = [agent.permission, session.permission, session.approved]   // 有序
  return rulesets.flatRules().filter(match(request)).last()  // findLast 优先
         ?? ASK_ALL
ask 流程: CompletableFuture<PermissionReply> 入 pendingRequests
  -> EventBus.publish(permission.asked) -> WS 推送 -> UI 弹窗
  -> reply(once|always|reject+feedback) -> complete future
  always: pattern 写 session.approved + 放行同会话其他 pending
  reject: 连带拒绝全部 pending, feedback 包装为 CorrectedError 返回模型
```

### 2.6 子代理（Task 工具 + Spawn 工具双通道）

**Task（同步/后台，OpenCode 模式）**：
```
execute(prompt, subagentType, taskId?, background?):
  1. depth 检查（沿 parentSession 上溯，>=2 拒绝）
  2. ask(permission:"task", patterns:[subagentType])
  3. taskId 存在 -> 复用子 session；否则 create(parentID=当前, 权限=父deny+task:deny+todo:deny)
  4. 子 loop 完整独立运行（自己的 prompt 组装/权限/事件流）
  5. 结果 = 最后一条 assistant text，包装 <task id state><summary/><task_result/></task>
  6. background=true: 入 BackgroundJob 池，立即返回启动凭证，完成时合成 user 消息注入父会话
```

**sessions_spawn（异步 announce，OpenClaw 模式）**：
```
execute(prompt, model?, timeout?, context?:"isolated"|"fork", visible?, category?):
  -> 创建隔离子会话，非阻塞返回 {runId, childSessionKey, sessionUrl?}
  -> 完成后 Announcer 推送到请求者（保留线程路由）
sessions_yield: 结束当前轮，子代理完成事件作为下一轮输入
subagents(list|cancel): 会话树视图/取消
```

### 2.7 会话队列与 Writer Claim

```java
class SessionLane {          // 每 sessionKey 一条 lane
  Deque<Runnable> queue;     // FIFO
  int concurrency = 1;       // lane 内严格串行
}
class GlobalLane {           // 全局并发帽
  Semaphore permits = agents.maxConcurrent;
}
// 提交流程
run 开始 -> INSERT session_active_writer(sessionKey, runId)  // claim
每次 transcript 写入 -> WHERE active_writer_run_id = ? 校验（乐观围栏）
run 结束 -> 释放 claim
```

**队列模式**：ChatSendService 按 session 配置分流：
- steer：`runtime.steer(text)` 注入活跃 run（工具边界生效，UI 标记"已插入"）
- followup：入 lane 队列下一轮
- collect：500ms 窗口合并
- interrupt：abort 当前 -> 最新消息入队

### 2.8 事件总线（双通道）

```java
class EventBus {
  publish(DurableEvent e)   // INSERT event 表 (aggregateID=sessionID, seq=全局序列)
                            // + WS 广播 (订阅该 aggregate 的连接)
  publish(LiveEvent e)      // 仅 WS 广播（delta 类）
}
```

- durable 事件（30+ 种）：session.next.prompt.admitted / step.started|ended|failed / text.started|ended / reasoning.* / tool.called|progress|success|failed / retried / compaction.* / revert.* / agent.switched / model.switched / task.updated…
- live 事件：*.delta（text/reasoning/tool.input/compaction）、session.status(busy/retry/idle)、permission.asked/replied、question.*、fs.edited、pty.*、tasks.changed、workboard.changed、config.changed、server.connected
- **回放**：`GET /api/session/{id}/event?after={seq}` 先重放 durable 再续 live（断线重连无缝）

### 2.9 LLM Provider 层

```java
interface LlmProvider {
  String id();                                        // openai-compatible / anthropic / ollama
  LlmStream stream(LlmRequest req);                  // SSE 流式
  CompletableFuture<JsonNode> generateObject(...);   // 小模型结构化（标题/摘要）
}
```

- 统一 `LlmEvent` 归一化（text-delta/reasoning-delta/tool-call/tool-result/usage/finish）
- ProviderConfig（opencode.json 兼容格式）：baseURL/apiKey/models{limit,modality}
- 重试策略：`RetryPolicy` 按 errorClass（RATE_LIMIT 指数退避 / 5xx 退避 / CONTEXT_OVERFLOW -> compact -> 重试 / AUTH 直接失败）
- UtilityModel 路由：标题/摘要/toolTitles 全部走低成本模型，失败回退主模型一次

### 2.10 记忆引擎

- 五层同需求文档；MemoryIndex = SQLite FTS5（chunks）+ 可选向量列（sqlite-vec）
- `memory_search`/`memory_get` 工具；bare /new 注入近 2 天日记
- Dreaming：CronScheduler 每日跑 `DreamingSweep`（读 episodic -> LLM 蒸馏候选 -> provenance 闸门 -> 写 MEMORY.md 候选区 -> 报告 DREAMS.md）
- provenance 闸门：origin_class=owner 才可直接晋升；transcript 来源需连续 2 次 dreaming 确认

### 2.11 插件与 Context Engine

```java
interface LobsterPlugin {                // ServiceLoader 或 jar 热加载
  List<Tool> tools();
  List<EventHook> hooks();               // before_tool_call / after_tool_call / before_prompt_build…
  Optional<ChannelAdapter> channel();    // 企业微信/钉钉/飞书…
  Optional<ContextEngine> contextEngine();
}
interface ContextEngine {                // 可插拔
  void ingest(SessionID, Message);
  AssembleResult assemble(SessionID, TokenBudget);  // -> messages + systemPromptAddition
  CompactResult compact(SessionID);
  void afterTurn(SessionID);
  default void prepareSubagentSpawn(...) / onSubagentEnded(...)
}
```

默认 `LegacyContextEngine`：ingest no-op / assemble 透传+sanitize+limit / compact 内置摘要。

### 2.12 定时与心跳

- Quartz 持久化到 SQLite（cron_jobs/cron_run_receipts 表）；错过触发补偿；runId 收据去重
- Heartbeat：每 agent 默认每日心跳任务（自我维护检查清单），HEARTBEAT_OK 静默 token

### 2.13 配置中心

- `~/.lobster/lobster.json`（OpenClaw 兼容风格）+ schema 驱动校验
- `config.patch` 增量合并（数组替换需 replacePaths）；reloadKind 三级：hot（即时生效）/ restart（标记待重启）/ none
- ui.prefs（主题/语言/侧边栏布局）随账号同步

### 2.14 安全设计

- 握手：`connect{auth.token}` -> 挑战 nonce 签名（设备密钥 ES256）-> 设备 token；scope（read/write/admin/pairing）
- RBAC：role -> allowedScopes -> 方法级 `@WsScope("operator.write")` 注解校验；MISSING_SCOPE 结构化错误
- Secrets：`secret_store_entries`（value 加密 AES-GCM，secret 类永不回显）；SecretRef 解析
- 沙箱（M5）：ToolExecutor 策略接口 -> LocalExec / DockerExec（挂载 workspace，network none）
- 审计：`audit_events` 只记元数据（runId/toolName/结果码/来源会话/决策人），30 天清理

## 四、性能与可靠性设计

| 项 | 方案 |
|---|---|
| 流式延迟 | delta 直接 WS 广播（不落库）；批量 flush 16ms 合帧 |
| SQLite 写入 | WAL + busy_timeout=5000 + 单写线程（WriteQueue）；part 批量 insert |
| 大会话 | 消息分页（cursor=seq）；历史加载 tail 200 条+惰性向上翻 |
| FTS | transcript_events 建 FTS5 虚表，写入时同步更新 |
| 崩溃恢复 | 重启时：重放未 promote 输入 -> 校验 active_writer（孤儿标记 interrupted）-> 重放 durable 事件恢复投影 |
| 备份 | `lobster backup` 命令（VACUUM INTO + workspace tar） |
| 前端性能 | Lit 细粒度更新；虚拟滚动长 transcript；工具卡片懒展开 |
